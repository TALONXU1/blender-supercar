# 赛道轨迹数据包 · 说明

这个包解决一件事：**让 F1 动画里的车在真实赛道上按真实物理跑，不可能漂移。**

不是"画一条好看的线"，是给车一套带时间戳的位姿表 + 一组不可违反的物理上限。
车每一帧的速度都被它所在弯道的抓地力卡住，所以它既不会飞出去，也不会慢得像玩具。

---

## 一、为什么不能直接手搓轨迹

你项目里现有的 `build_f1_rig_and_drift_animation.py` 这类脚本，位移和朝向是手写的关键帧。
手搓轨迹必然出现两个破绽：

1. **弯心速度不受约束** —— 车以 200 km/h 过 40 m 半径的弯，物理上需要 7.9 g，F1 做不到。观众说不出为什么，但会觉得假。
2. **朝向和路径不同步** —— 用位移差反推车头朝向，在采样疏的地方会跳变，看起来就是一抖一抖地滑。

真实赛道上，车速是**由弯道半径决定的**，不是由你想要的节奏决定的。这套数据把这个约束代进去了。

**银石 Silverstone**
- 周长 5.834 km ／ 官方 5.891 km ／ 误差 **−0.97%**
- 仿真单圈 90.34 s ／ 官方杆位 87.0 s ／ 误差 **+3.84%**
- 平均 232.5 km/h，峰值 331 km/h，最低 54 km/h
- 2933 个采样点，间隔 2 m，严格闭环
- 几何质检：拼接缺口 0.00 m，大于 20 m 的断点 0 个
- 横向加速度峰值 6.39 g，超限点 0 个 → **PASS**

**蒙扎 Monza**
- 周长 5.750 km ／ 官方 5.793 km ／ 误差 **−0.75%**
- 仿真单圈 79.57 s ／ 官方杆位 80.5 s ／ 误差 **−1.16%**
- 平均 260 km/h，峰值 331 km/h，最低 40 km/h
- 2888 个采样点，缺口 0.00 m
- 横向加速度峰值 5.81 g，超限点 0 个 → **PASS**

怎么读这两组数：**圈速误差在 ±4% 以内，说明速度模型是对的。**
如果一条赛道算出来比官方慢 30%，那不是车慢，是几何数据有问题，别用。

## 四、数据长什么样

不是一条曲线，是一张表。每个点包含：

| 字段 | 含义 | 怎么用 |
|---|---|---|
| `t` | 该点被经过的时刻（秒） | **唯一驱动变量**。按它插值 |
| `racing_xy` | 赛车线坐标（米） | 车的实际位置走这条 |
| `xy` | 赛道中心线坐标 | 只用来建路面，不用来跑车 |
| `heading_deg` | 车头朝向（度） | 直接赋给车的 Z 轴旋转 |
| `v_mps` | 该点速度（米/秒） | 决定位移节奏 |
| `curv_1pm` | 曲率（1/米） | 算前轮转角、算横向加速度 |
| `lat_g` | 横向加速度（g） | 自检用 |
| `s` | 沿中心线弧长（米） | 需要按距离排布元素时用 |

坐标系：局部平面，米制，原点在中心线起点，z=0（未做高程）。
`meta.georef` 里有经纬度反查参数，要贴卫星图才用得上。

### 第 2 步 挂到你的车上

打开 `scifi_f1_2035_v4_racing.blend`（或你当前的车型文件），
Scripting 面板打开 `blender_apply.py`，改顶部 CONFIG 三行：

```python
"json": r"D:\项目session\blender-supercar\track_data\silverstone_track.json",
"car_obj": "写你场景里车物体的真实名字",
"wheels": ["Wheel_FL", "Wheel_FR", "Wheel_RL", "Wheel_RR"],   # 轮子物体名
```

Run。它会：
- 自动建一条 14 m 宽的赛道中心线曲线（当对位参考，不用可以关掉）
- 按 `t` 烘焙车的位移和朝向关键帧
- 按 `v/0.33` 烘焙四个轮子的转速
- 按 `curv × 3.6` 烘焙前轮转角
- 最后自检，打印 `PASS` 或 `FAIL` 和最大横向加速度

看到 `PASS` 就说明这一圈物理上成立。

### 第 3 步 环境随便加

轨迹跟环境完全无关。护栏、路肩、看台、树，随便摆，都不会影响车的运动。
只有一件事要注意：**路面宽度要和数据对上**，`meta.track_half_width_m` 是 7.0 m，
也就是路宽 14 m。路面做窄了车会压到草地，看着就出戏。

## 六、四条禁令（违背任何一条都会飘）

这四条不是建议，是这套数据能成立的前提。
如果你让 agent 去改 `blender_apply.py`，务必把这段话一起给它：

1. **按 `t` 插值取位置，不许按帧均分。**
   按帧均分 = 匀速跑。真车在直道 330 km/h、弯心 80 km/h，匀速是外行最容易露馅的地方。

2. **朝向用 `heading_deg`，不许用位移差反推。**
   位移差在采样点稀疏处会跳变，表现为车头一顿一顿。

3. **位置走 `racing_xy`，不是 `xy`。**
   `xy` 是中心线。压着中线跑，弯里看着像轨道车。

4. **关键帧插值设 LINEAR，禁 Bezier。**
   Bezier 在弯心会过冲，车轮冲出赛道——**九成的"漂移"事故都发生在这**。
   `blender_apply.py` 已经强制设成 LINEAR 了，别人改脚本时最容易把它改回去。

## 七、换赛道

```
python build_track.py "赛道名" 官方公里 官方圈速 --probe
```

`--probe` 只看两件事：
- `length_error` 在 ±3% 内
- `big_gaps` 为 0

两条都过，再跑正式生成。不过说明这条赛道在 OSM 里没连好。

**已知能用的**：银石、蒙扎、红牛环（有缺口但可接受）
**已知不能用的**：摩纳哥（缺口 400 m 以上）、新加坡、斯帕、铃鹿、赞德沃特、英特拉格斯（OSM 里根本没有 type=circuit 关系）

街道赛普遍是断的，因为它们是普通市政道路。要用就得从官方赛道图手描点存成 csv，
然后送进 `blender_apply.py`，那是另一个工作量。

## 八、数据来源与署名

赛道几何来自 OpenStreetMap，许可 ODbL。
公开发布片子时按 ODbL 要求署名：`© OpenStreetMap contributors`。
自己项目内部使用不需要额外交代。

速度模型是我按 F1 公开的下压力/抓地力参数拟合的，不是官方遥测数据：
- 横向极限 `a = 15.0 + 0.00714 · v²`（低速约 1.5 g，250 km/h 约 5 g）
- 制动 `min(55, 20 + 0.005 · v²)`
- 加速 `min(16, 937 / v)`（单位质量功率 937 W/kg）

所以它的精度是"看着完全对"，不是"逐帧对齐真实遥测"。做视觉动画足够了。
