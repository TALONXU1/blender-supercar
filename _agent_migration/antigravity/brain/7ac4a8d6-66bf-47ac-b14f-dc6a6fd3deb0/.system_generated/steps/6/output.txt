The query relates to **OpenDesign** (`nexu-io/open-design`), an open-source, local-first collaborative AI design agent workspace (often used as an alternative to Claude Design)[1][2], and its **Motion** features[3] utilizing the **Model Context Protocol (MCP)** and CLI integrations[1][4].

### Connecting OpenDesign Motion via MCP & CLI

OpenDesign connects to coding agents and external tools using skills, a CLI daemon, and MCP (Model Context Protocol) servers[1][4]. 

#### 1. Using CLI Integration
OpenDesign auto-detects and integrates with various local terminal agent CLIs (such as Claude Code, Codex, Gemini CLI, Cursor Agent, etc.)[5][6]. 
* **Supported CLI Management:** You can manage or inspect connected runtimes via the desktop app under `Settings` $\rightarrow$ `Models & providers` $\rightarrow$ `Local CLI`[7].
* **Daemon & Binary:** The app spins up a local background daemon (`apps/daemon`) which exposes helper commands like `od` for managing agent pipes and MCP linkages[4].

#### 2. Connecting via MCP (Model Context Protocol)
To let an external agent or client interact with your active OpenDesign workspace and Motion projects:
1. Open the OpenDesign desktop app[8].
2. Navigate to **Settings → OpenDesign MCP**[8].
3. Select your target agent or client from the configuration menu[8].
4. Copy the automatically generated device-specific CLI command or JSON configuration block for your client[8]. 
   * *Example pattern for CLI-based MCP registration (e.g., Claude Code or custom clients):*
     ```bash
     od mcp install claude
     ```
     *(Or manually mapping standard JSON transport parameters in your agent's configuration files).*
5. Keep OpenDesign running locally so the external agent loop can successfully communicate through the sidecar protocol[8].
