# compiled/ — 成品提示词

由 `../prompt_library.json` 通过 `../build_prompts.py` 生成。**不要手改这个目录里的文件**，改 JSON 再重跑。

```bash
python scenes/prompts/build_prompts.py
```

## 两个版本

| 目录 | 内容 | 词数 | 用途 |
|---|---|---|---|
| `compiled/*.txt` | 正文 + core(62) + scene(23–46) | 约 90–110 词限制 | **默认直接用** |
| `compiled/strict/*.txt` | 上面 + full(112) | 约 200–220 词限制 | 默认版出图不合格时 |

## 每个文件的结构

```
# 场景名
# 比例 16:9   限制词 87 词 / 正文 213 词 = 41%
# 备注 <这张的已知坑>

<正文：镜头 + 天气 + 环境 + 车体 + 质量>

<限制尾巴：core + scene>
```

前三行是注释，粘贴时从空行之后开始。

## 返工顺序

出图不合格时按这个顺序加，别一上来就上 strict：

1. 检查 `scene` 那 3–4 条是否覆盖了实际画错的东西。画错的东西不在里面 → 补一条到 JSON 的 `negative_scene`
2. 还是错 → 换 `strict/` 版本
3. 还错 → 说明是**措辞问题不是限制问题**，回到正文改正面描述（例如"要更湿"改成 `mirror-wet with standing water`，而不是再加一句 `no dry`）

第 3 条是最常见的浪费：反复加禁令解决不了正面描述不清的问题。
